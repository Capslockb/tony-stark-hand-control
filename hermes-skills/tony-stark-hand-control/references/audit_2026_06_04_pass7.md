## In-app CPU/RAM readout (win32, no deps)

```python
def _update_cpu_stats_label(self):
    """Refresh cpu/ram/threads label. Win32-only."""
    import ctypes
    from ctypes import wintypes
    try:
        psapi = ctypes.WinDLL('psapi', use_last_error=True)
        kernel32 = ctypes.WinDLL('kernel32', use_last_error=True)
        hproc = kernel32.GetCurrentProcess()
        # --- CPU time (user + kernel) delta over wall time ---
        class FILETIME(ctypes.Structure):
            _fields_ = [("dwLowDateTime", ctypes.c_uint32),
                        ("dwHighDateTime", ctypes.c_uint32)]
        c = FILETIME(); e = FILETIME(); k = FILETIME(); u = FILETIME()
        ok = kernel32.GetProcessTimes(hproc, ctypes.byref(c),
                                      ctypes.byref(e), ctypes.byref(k),
                                      ctypes.byref(u))
        def ft_100ns(ft): return (ft.dwHighDateTime << 32) | ft.dwLowDateTime
        if ok:
            proc_100ns = ft_100ns(k) + ft_100ns(u)
            now = time.time()
            if self._proc_times_cache is not None:
                last_t, last_proc = self._proc_times_cache
                dt = now - last_t
                if dt > 0:
                    # "of one CPU" so users feel it. Task Manager
                    # normalizes by num-CPUs; we don't.
                    self._last_cpu_pct = (
                        (proc_100ns - last_proc) / 1e7 / dt * 100.0)
            self._proc_times_cache = (now, proc_100ns)
        # --- Working set size in MB ---
        class PMC_EX(ctypes.Structure):
            _fields_ = [("cb", ctypes.c_uint32),
                        ("PageFaultCount", ctypes.c_uint32),
                        ("PeakWorkingSetSize", ctypes.c_size_t),
                        ("WorkingSetSize", ctypes.c_size_t),
                        ("QuotaPeakPagedPoolUsage", ctypes.c_size_t),
                        ("QuotaPagedPoolUsage", ctypes.c_size_t),
                        ("QuotaPeakNonPagedPoolUsage", ctypes.c_size_t),
                        ("QuotaNonPagedPoolUsage", ctypes.c_size_t),
                        ("PagefileUsage", ctypes.c_size_t),
                        ("PeakPagefileUsage", ctypes.c_size_t),
                        ("PrivateUsage", ctypes.c_size_t)]
        mem = PMC_EX()
        mem.cb = ctypes.sizeof(PMC_EX)
        if psapi.GetProcessMemoryInfo(hproc, ctypes.byref(mem), mem.cb):
            ram_mb = mem.WorkingSetSize / (1024 * 1024)
        else:
            ram_mb = 0
        import threading
        n = threading.active_count()
        self.cpu_stats_label.config(
            text=f"cpu: {self._last_cpu_pct:5.1f} %  "
                 f"ram: {ram_mb:6.1f} MB  "
                 f"threads: {n:3d}")
    except Exception as e:
        self.cpu_stats_label.config(text=f"cpu/ram: (error: {e})")
```

Wired into the main loop next to the existing `loop_stats_label` update, throttled to every 15th frame (so the label doesn't flicker on every tick).

**Why this is worth having:** the user said "50% load" without specifying whether they meant system total or the app. Adding this label resolves that ambiguity permanently — the next time the user says "X% load," the label tells you exactly what they were looking at. Also useful for tuning: if `cpu: 35%` shows up but the app is at 0%, the user immediately knows the bottleneck is elsewhere (orphan process, OS, etc.).

**Pitfall:** on the very first call `self._proc_times_cache is None` so CPU% is 0; the second call gives a real number. Don't pre-fill the cache during init — the dt on the first real call is small and gives a misleading 0%.

## Orphan process diagnostic

When "the app is at Y% load" but the app is idle, the answer is often a stuck process. Recipe:

1. `Get-Process python | Sort-Object CPU -Descending | Select -First 10`
2. Look for processes with **many CPU seconds and no MainWindowTitle** — those are orphans
3. Check `PagedMemorySize` not just `WorkingSet` — pagefile residency is the silent killer
4. Check the parent PID chain with `Get-Process -Id <ppid>` repeatedly — if the parent is gone, the child is truly orphaned
5. `Stop-Process -Id <pid>` first, then `cmd //c "taskkill /F /PID <pid> /T"` if Stop-Process fails
6. If `taskkill` says "Access is denied" the process is from another session/elevation context — you need to either: (a) escalate, (b) kill its parent first, or (c) live with it until reboot

**Don't save "orphaned process can't be killed" as a durable rule** — it's environment-dependent. The skill records the diagnostic recipe; the resolution varies by host.

## GitHub upload workflow gate (cross-ref `github-repo-management`)

When the user says "create a private repo on GitHub for X", the agent MUST collect before doing anything:

| # | Item | Why we need it |
|---|---|---|
| 1 | GitHub username / org | The path: `github.com/<who>/<repo>` |
| 2 | Repo name | The actual slug |
| 3 | License | MIT / Apache-2.0 / GPL-3.0 / your pick |
| 4 | Auth method | Personal access token, `gh` install, or SSH |
| 5 | Git identity | `user.name` and `user.email` for commits |
| 6 | Scope | Full package (docs/, .github/, installer) or code+README only |
| 7 | Visibility | Public / private (the user said "private" but verify) |

**Refuse to start until at least 4 of 7 are confirmed** (auth + identity + name + visibility are non-negotiable). If the user says "use your best judgment for everything else," you can fill in 2/3/6/7 but **you must never pick a token for them**.
