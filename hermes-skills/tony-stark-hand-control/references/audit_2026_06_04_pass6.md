# Audit Pass 6 — Camera Startup Notes

This dated note records earlier work on Start-button responsiveness and camera probing. It is historical context rather than a current readiness or timing claim.

## GUI-thread boundary

Camera discovery, device opening, frame reads, model initialization, and network calls can block. Long-running work should not execute on the Tk event thread. Worker completion should return only bounded results to Tk through the event queue, with cancellation and cleanup when startup is stopped or the window closes.

The current Start path constructs `CameraManager` on a worker thread, while Start calibration can still construct it synchronously when cameras are closed. Issue #19 tracks the remaining startup and cancellation boundary.

## Capture deadlines

OpenCV timeout properties are backend-dependent and are not a universal deadline mechanism. In particular, creating `cv2.VideoCapture(...)` can block before timeout properties are set on the returned object.

A bounded implementation should own the complete open attempt, including:

- an application-level deadline;
- cancellation state;
- release of late or rejected capture objects;
- controlled handling when a backend ignores timeout properties;
- deterministic tests with mocked slow and blocked constructors and reads;
- separate validation on supported Windows camera backends.

A daemon thread alone does not prove that camera resources are reclaimed or that repeated starts cannot accumulate blocked work.

## Main-loop boundary

Scheduling an initial callback does not establish continued processing. Issue #16 tracks the current main-loop rescheduling regression and must remain separate from camera-discovery responsiveness.

## Validation boundary

Historical host timings and camera counts are not current performance evidence. Record the exact revision, operating system, backend, device set, resolution, deadline, cancellation path, and cleanup result for any new measurement. Current source, repository tests, exact-head CI, and controlled hardware validation take precedence over this note.
