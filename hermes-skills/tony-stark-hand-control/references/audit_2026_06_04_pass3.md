## 16. Dead-code duplicate method shadowing the newer one

`CameraManager` ended up with **two** `release()` methods after a
series of patches:

```python
# Original (lines 404-406 in the old layout):
def release(self):
    for cap in self.cameras:
        cap.release()

# Newer (lines 348-352, with try/except + clears the list):
def release(self):
    for cap in self.cameras:
        try: cap.release()
        except Exception: pass
    self.cameras = []
```

Python class definitions take the LAST one as the effective method.
The first (older, unsafe) is dead code that just confuses readers
and search tools. It also bloats the AST/line count.

**Symptom:** a duplicate function warning from `ast` introspection
that lists both methods, even though only one is callable.

**Detection rule:** any time you patch a method's name (e.g. add
error handling, change semantics), **find and remove the older
copy** rather than relying on Python's last-definition-wins. The
older copy may have subtle behavior the new one doesn't (in this
case, the older one didn't clear `self.cameras`, leaving zombie
references).

```python
# AST audit that finds the duplicate:
import ast
tree = ast.parse(open('the_file.py').read())
for node in ast.walk(tree):
    if isinstance(node, ast.ClassDef):
        method_names = [m.name for m in node.body
                        if isinstance(m, ast.FunctionDef)]
        dupes = {n for n in method_names if method_names.count(n) > 1}
        if dupes:
            print(f"{node.name}: duplicate methods {dupes}")
```

## 17. `save()` reads a key that `load()` may not have populated

`StereoCalibrator.save()` did `payload[f'P_{i}'] = c['P']` but
real calibration dicts only got the `'P'` key when built by
`calibrate_all()`. A calibration synthesized by tests, or loaded
from a file pre-dating the P addition, would crash on save with
`KeyError: 'P'`.

**Fix pattern:** any time `save()` reads a derived key from a
struct, compute it on the fly if missing. The save method is the
one place in your code that absolutely cannot fail, because losing
user data is worse than producing an inelegant output.

```python
for i, c in enumerate(self.calibrations):
    if c is None:
        continue
    payload[f'K_{i}'] = c['K']
    payload[f'dist_{i}'] = c['dist']
    payload[f'R_{i}'] = c['R']
    payload[f't_{i}'] = c['t']
    # Compute P if missing -- calibrate_all stores it, but
    # load() from old files or test fixtures may not.
    if c.get('P') is not None:
        payload[f'P_{i}'] = c['P']
    else:
        payload[f'P_{i}'] = c['K'] @ np.hstack((c['R'], c['t']))
```

**General principle:** "save" is sacred. It should be:
1. **Idempotent** — calling it twice produces the same file
2. **Lossless** — no data the user gave you should be dropped
3. **Robust to old versions** — `load(path); save(path)` should
   always be a no-op or a clean upgrade, never a crash

## Desktop GUI headless self-test recipe

The single most useful pattern from this audit was the
**headless-construction test** — build the entire app without
showing a window, then exercise every class and method that
can be tested without a main loop.

```python
import tkinter as tk
import importlib.util
import numpy as np

# Load the app file as a module without running its main block
spec = importlib.util.spec_from_file_location(
    'app', r'C:/path/to/app.py')
m = importlib.util.module_from_spec(spec)
spec.loader.exec_module(m)   # executes class defs and module-level code

# Construct the app with a withdrawn root -- no window appears
root = tk.Tk()
root.withdraw()
app = m.HandControlApp(root)
assert isinstance(app.hand_proc, m.HandProcessor)
# ... exercise every method

app.on_close()  # exercises cleanup paths too
root.destroy()
```

**Why this works for desktop GUI apps:**
- All class definitions execute, so any import errors / syntax
  errors / `__init__` mistakes surface
- `Tk().withdraw()` shows no window — no need to interact
- Widget construction runs (catches `bad widget name`,
  `unknown option`, `__init__` errors in `_build_*_tab`)
- `on_close()` exercises every cleanup path (worker thread
  stop, CameraManager release, after_id cancel, JSON save)

**Then** for each subsystem, write a focused test that doesn't
require the GUI at all:

```python
# CameraManager (real cameras)
cm = m.CameraManager(width=480, height=360, fps=30)
assert len(cm.cameras) >= 1
ret, frame = cm.read_all()[0]
cm.release()

# HandProcessor (synthetic frames)
hp = m.HandProcessor.__new__(m.HandProcessor)
m.HandProcessor.__init__(hp)
for _ in range(5):
    hp.smooth(hp.index_tip, 0.5, 0.5, dt=1/30)
p = hp.predict(hp.index_tip)
assert p is not None

# Pure-Python classes (RoomMap, triangulate, etc.) — no setup
rm = m.RoomMap()
a = rm.add(0, 0, 0, atype='wall')
rm.save(temp_path)
rm2 = m.RoomMap(); rm2.path = temp_path
assert rm2.load() and len(rm2.anchors) == 1
```

**Test budget for a 3,000-line app: ~60-80 assertions across 5-6
subsystems catches ~80% of bugs in a single ~10-second run.**

## Live runtime test for the live app

Beyond headless tests, run the actual app and watch its output:

```bash
cd /c/Users/Bernardo/tony_stark_hand_control
python tony_stark_hud_control.py
```

Then in another terminal:

```bash
# List background processes
hermes process list
# Check the process is still alive and has been running
hermes process poll proc_xxx
# Read the stderr/stdout for silent errors
hermes process log proc_xxx
```

**What to look for:**
- The `HandProcessor: GPU delegate unavailable -> CPU` line should
  appear exactly once (per process). If it appears in a loop, the
  inference worker is crashing and restarting.
- `W0000 ... feedback manager requires a model with a single
  signature inference` is a benign MediaPipe warning — it's
  expected, don't try to suppress it.
- NVidia camera driver spam (`VCAMDS VidFilter Out FPS`) is also
  benign. Filter it out of the user's log with `grep -v VCAMDS`.
- A clean process log of 30+ seconds with no exceptions after the
  startup banner is the green light that the runtime is healthy.
