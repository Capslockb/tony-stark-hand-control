# Audit Pass 2 — Historical Findings

This dated note summarizes defects and optimization ideas from one development revision. It is not a current specification, performance report, or proof that the listed corrections remain present.

## Areas reviewed

The review covered:

- motion-prediction anchors and no-data behavior;
- mirror-invariant palm-open detection;
- normalized click-distance calculations;
- camera-handle ownership during calibration and restart;
- optional network-classifier failure handling;
- Windows focus-overlay structures;
- asynchronous MediaPipe submission;
- feed and FPS caching;
- fast-mode resizing;
- cursor-motion clamping;
- loop timing and 3D-view scheduling.

## Durable validation patterns

Current regressions should test behavior rather than preserve historical literal values.

Useful boundaries include:

1. unseen landmarks return an explicit no-data result;
2. mirrored and rotated landmark geometry does not depend on one image axis;
3. thresholds use documented coordinate units;
4. every camera and worker resource has deterministic release behavior;
5. network failures are time-bounded and do not use real credentials;
6. asynchronous results retain their camera/source ownership;
7. GUI updates remain on the Tk event thread;
8. cached values are invalidated when their inputs change;
9. performance measurements record revision, host, camera configuration, resolution, sample count, and method;
10. repository-wide discovery runs without cameras, a display, network access, or optional services.

## Current blockers

Historical descriptions of repeated main-loop processing are superseded by Issue #16, which tracks the current rescheduling regression. Historical multi-camera inference descriptions are also subject to Issue #7's result-ownership boundary. Camera-open timing and cancellation remain tracked separately and require deterministic slow/blocking-open tests.

## Validation boundary

Machine-specific timings, fixed FPS claims, copied snippets, and local smoke results are not current acceptance evidence. Current source, current issues, repository tests, exact-head workflow results, and controlled hardware validation take precedence over this note.
