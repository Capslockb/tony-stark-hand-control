# Audit pass 2026-06-04 (second pass)

Findings from the second end-to-end audit of `tony_stark_hud_control.py`
(many of these were bugs the first audit missed or regressions from
later patches). Each item below is the canonical pattern to use, with
the broken pattern called out so the lesson is durable.

## 1. Motion-predictor velocity must come from `prev_filtered`, not `predicted`

The first version of `HandProcessor.smooth()` computed velocity as
`(filt - self.predicted[tip_id]) / wall_dt`. But `self.predicted` was
the **previous call's smoothed average** (set at the END of the prior
`smooth()`), not the previous filtered point. Result: velocity was
massively underestimated and the predictor couldn't extrapolate.

**Fix:** save the previous filtered value BEFORE overwriting
`self.filtered[tip_id]` and use that as the velocity basis.

```python
prev_filtered = self.filtered[tip_id]              # save first
filt = self._one_euro_filter(prev_filtered, (x, y), dt, ...)
self.filtered[tip_id] = filt
...
if prev_filtered is not None and self._last_smooth_ts[tip_id] > 0:
    wall_dt = ts - self._last_smooth_ts[tip_id]
    if wall_dt > 1e-4:
        vx = (filt[0] - prev_filtered[0]) / wall_dt  # <-- prev_filtered, not predicted
        vy = (filt[1] - prev_filtered[1]) / wall_dt
```

**Also:** the prediction anchor should be the **freshest filtered
point**, not the buffer average. Buffer average lags behind, and the
predictor's anchor needs to track the latest detection for the
extrapolation horizon to be accurate.

```python
self.predicted[tip_id] = (filt[0], filt[1], ts)   # anchor on filt, not buffer mean
```

## 2. `predict()` must return `None` for unseen tips, not `(0, 0)`

Returning `(0, 0)` for an unseen tip made gesture code register a
fake click in the top-left corner of the screen. Return `None` and
have callers fall back to the raw landmark for that single tip.

```python
def predict(self, tip_id, now=None):
    if pts <= 0:
        return None                       # <-- not (0, 0)
    ...
```

Caller pattern in `handle_gestures`:

```python
def _px(tip_id, raw_lm):
    p = self.hand_proc.predict(tip_id, now=now)
    if p is None:
        return (raw_lm.x, raw_lm.y)       # fall back to raw
    return p
```

## 3. `is_palm_open` MUST be wrist-relative, not Y-axis-based

The naive Y-flip check `landmarks[tip].y < landmarks[pip].y` is broken
on selfie cameras (which mirror the Y axis) and on rotated hand poses.
**MOST SELFIE WEBCAMS ON WINDOWS MIRROR THE Y AXIS BY DEFAULT.**

Use the wrist-relative test:

```python
@staticmethod
def is_palm_open(landmarks):
    if not landmarks or len(landmarks) < 21:
        return False
    wrist = landmarks[0]
    fingers = [(8, 6, 5), (12, 10, 9), (16, 14, 13), (20, 18, 17)]
    def dist(a, b):
        return math.hypot(a.x - b.x, a.y - b.y, a.z - b.z)
    extended = 0
    for tip, pip, mcp in fingers:
        wrist_to_tip = dist(wrist, landmarks[tip])
        wrist_to_pip = dist(wrist, landmarks[pip])
        wrist_to_mcp = dist(wrist, landmarks[mcp])
        if wrist_to_tip > wrist_to_pip * 1.15 \
                and wrist_to_pip > wrist_to_mcp * 0.95:
            extended += 1
    return extended >= 3
```

Verified with a synthetic test (`palm_test.py`): the OLD Y-flip code
returns `False` for a mirrored-Y palm; the NEW wrist-relative code
returns `True`. This is the single most common reason the engage
gesture fails on Windows selfie webcams.

## 4. Click distance must be normalized, not pixel-based

The old `d` lambda in `handle_gestures` did:

```python
d = lambda a, b: math.hypot((a.x-b.x)*self.screen_width, (a.y-b.y)*self.screen_height)
th = self.click_threshold_px
```

That's a 2D distance in screen pixels, but `a.x, b.x` are in
normalized camera coords for two different cameras at different
resolutions. Mixing units and across-camera-image-sizes made the
threshold meaningless.

**Fix:** use pure normalized distance and auto-scale the threshold:

```python
d_norm = lambda a, b: math.hypot(a.x - b.x, a.y - b.y)
th = self.click_threshold_px / max(self.screen_height, 1) * 4
```

The 40 px default on a 1080p screen -> ~0.15 normalized, which is a
sensible thumb-touching-index radius.

## 5. Camera handle leak on calibration

`start_calibration()` opened a `CameraManager` and stored it in
`self.camera_mgr`. If the user then clicked **Start** without first
clicking **Stop** in the right place, the new `CameraManager()` was
assigned on top of the old one, **leaking the old cv2.VideoCapture
handles** (the GC eventually released them, but the `isOpened()` calls
on subsequent start-ups could fail with conflicting handle states).

**Fix:** add `CameraManager.release()`, call it from `start()` and
`stop()`, and have `start_calibration()` release the temporary
manager it opened after the calibration finishes.

```python
class CameraManager:
    def release(self):
        for cap in self.cameras:
            try: cap.release()
            except Exception: pass
        self.cameras = []
```

```python
# In start():
if self.camera_mgr is not None:
    self.camera_mgr.release()
    self.camera_mgr = None
# ... then create new one
```

## 6. Ollama circuit breaker (do not retry-storm on a dead endpoint)

`OllamaGestureRecognizer` was making one network call every Nth tick
with an 8s timeout. If the endpoint was unreachable (e.g. ollama.com
blocked), the worker thread was stuck for 8s on every request, and
the error log spammed. Add a circuit breaker: 3 consecutive failures
=> 30s cooldown, no requests, no work.

```python
def _record_failure(self, msg):
    self._consecutive_failures += 1
    if self._consecutive_failures >= self._failure_threshold:
        self._failure_cooldown_until = time.time() + 30.0

def submit_frame(self, frame):
    if now < self._failure_cooldown_until:
        return  # skip silently during cooldown
```

Reset the counter on any 2xx response.

## 7. Persistent selection overlay via Win32 GetGUIThreadInfo

The user wanted a persistent visual indicator of which UI element
has focus, not just a 400ms flash on each swipe. Win32 has the
`GetGUIThreadInfo` API which returns the focused control inside the
foreground thread's GUI; polling it 10x/sec gives a smooth selection
indicator.

**CRITICAL: `GUITHREADINFO.cbSize` MUST be set before the call,**
otherwise the API returns zeros and the overlay highlights the entire
screen.

```python
import struct
gui_info = ctypes.create_string_buffer(72)
struct.pack_into('I', gui_info, 0, 72)                # cbSize FIRST
ok = ctypes.windll.user32.GetGUIThreadInfo(thread_id, gui_info)
focus_hwnd = struct.unpack_from('P', gui_info, 16)[0]
```

Overlay = a Toplevel window with `overrideredirect(True)`,
`attributes('-topmost', True)`, plus the WS_EX_TRANSPARENT |
WS_EX_LAYERED | WS_EX_TOOLWINDOW extended style bits (via ctypes)
so it never blocks clicks.

## 8. Async MediaPipe inference thread (the single biggest perf win)

The hot path was the main Tk loop calling `self.hand_proc.detect(frame)`
synchronously -- that blocks for ~25-30ms on CPU. With 4 cameras and
~20ms camera reads, the loop was 100% blocked on MediaPipe.

**Fix:** `HandProcessor.detect()` enqueues a frame on a small
thread-safe queue (`maxsize=2`) and returns the most-recent cached
result immediately. A background thread (`_inference_worker`) does
the actual `detect_for_video` call and writes back into `_last_result`
under a lock. Main-thread `detect()` call time drops to **0.001 ms**.

```python
def detect(self, frame):
    if self._inference_pending:
        return self._last_result
    self._inference_pending = True
    rgb = cv2.cvtColor(frame, cv2.COLOR_BGR2RGB)
    if not rgb.flags['C_CONTIGUOUS']:
        rgb = np.ascontiguousarray(rgb)
    self._infer_q.put((rgb, int(time.time() * 1000)))
    return self._last_result

def _inference_worker(self):
    from queue import Empty
    while not self._stop_worker:
        try:
            rgb, ts = self._infer_q.get(timeout=0.5)
        except Empty:
            continue
        # bump ts if not monotonic, then call detector.detect_for_video
        ...
```

Set `self._stop_worker = True` on app close so the thread exits
cleanly. The 0.5s `get(timeout=)` lets the thread check the stop flag
even when the queue is empty.

## 9. Throttle expensive per-frame probes

Inside the main loop, several things were re-computed every frame even
though they change slowly:

- `is_feed_live()` -- std + mean over 480x360 grayscale. ~1ms x 4 cams.
  --> Re-check every 10th frame. Cache in `self._live_cache[i]`.
- `get_actual_fps(i)` -- driver query, ~0.1ms x 4 cams.
  --> Re-check every 30th frame. Cache in `self._fps_cache[i]`.
- `display = frame.copy()` for the HUD overlay -- ~0.5ms x 4 cams.
  --> Reuse `self._last_displays[i]` between MediaPipe runs; only
      `.copy()` on frames where the landmark changed.

These are boring micro-optimizations but together they recover ~3-5ms
per main loop iteration, which is the difference between 30 fps and
~22 fps on this 4-cam / CPU-MediaPipe setup.

## 10. Fast Mode: 240p pre-downscale before MediaPipe

MediaPipe's HandLandmarker does its own internal resize, but the
pre-processing cost (BGR -> RGB, contiguous array, mp.Image
wrapper) scales with input pixels. Pre-downscaling to 240p before
MediaPipe cuts the model forward-pass time by ~30% at a small
accuracy cost on tiny / far-away hands. Toggle from the Tracking tab.

```python
if self.fast_mode and frame.shape[0] > 240:
    scale = 240.0 / frame.shape[0]
    frame_in = cv2.resize(frame, (new_w, new_h), interpolation=cv2.INTER_AREA)
else:
    frame_in = frame
```

## 11. Velocity clamp for screen cursor: 10000 px/s, not 5000

With the predictor upstream, the input to the screen EMA is already
very accurate. The old 5000 px/s clamp was actively throttling the
cursor (5 px per ms when the user moves fast). Bump to 10000 px/s so
only absurd teleports (jitter on lost detection) get clamped.

## 12. Predict decay is `(1 - (dt/max)^2)`, NOT `0.5 * (1 - (dt/max)^2)`

The original comment claimed the decay formula was `0.5 * (1 - ...)`
which is wrong math. The actual code is correct -- it's a soft
ease-out curve from 1.0 at dt=0 to 0.0 at dt=max_dt, with the first
half of the prediction horizon nearly full-strength. Just fix the
docstring to match.

self._loop_ms_hist.append(elapsed_ms)
if self._frame_counter % 15 == 0 and self._loop_ms_hist:

## 14. 3D room-mapping tab (matplotlib 3D viewport inside Tk)

The 3D / Room tab embeds a `matplotlib.backends.backend_tkagg.FigureCanvasTkAgg`
inside a ttk.Frame. Useful patterns:

- Lazy-import matplotlib so the rest of the app still works if it's
  missing.
- Use `proj3d.inv_transform` to back-project a 2D click into a 3D world
  ray, then intersect with the user's chosen z-plane to drop anchors.
- Throttle the matplotlib redraw with a coalesced `self.root.after(33, ...)`
  so multiple per-frame `clf()`+`draw_*` calls don't pile up.
- Add a `RoomMap` class with `add/remove/clear/save/load`, persisted to
  a JSON file next to the script. Auto-save on `on_close`.
- Auto-fit the axes bounds to include all points (cameras, anchors, hand)
  each redraw -- the user shouldn't have to manually zoom out to see
  their hand if it's currently at z=2m while the cameras are at z=1m.

## 15. Camera "live feed" check thresholds are easy to over-tighten

Default of `min_std=2.0, min_brightness=3.0` is correct for a normal
lit scene but rejects 75% of webcam feeds at low-light / IR. For a
4-camera setup with at least one dark/IR cam, this looks like "all
cameras are black".

Use `min_std=0.5, min_brightness=0.2` -- a near-uniform frame (std ~0
and brightness ~0) is what's really broken; a dim but live scene
(std >= 0.5, brightness 0.2-1) is fine and should be kept.
