# June 2026 Audit Summary

This file is a historical index of defects discussed during one development period. It is not a statement that the defects remain fixed, that the listed tests still exist, or that current behavior has been validated.

## Areas reviewed

The review considered:

- smoothing state and prediction anchors;
- missing-data handling;
- mirror-invariant palm-open detection;
- normalized gesture thresholds;
- optional network-classifier failure handling;
- camera-handle ownership and release;
- dark-frame heuristics;
- initialization order for shared UI and worker settings;
- cursor-motion clamping and timing assumptions.

These observations were tied to particular revisions. Current implementations and defaults may differ.

## Durable testing lessons

Focused regressions should cover:

1. no-data states without synthesizing valid coordinates;
2. mirrored and non-mirrored landmark geometry;
3. settings construction and propagation before first use;
4. camera, file, socket, and worker cleanup on all exit paths;
5. network timeouts and bounded recovery without real credentials;
6. normalized thresholds across different frame and display dimensions;
7. deterministic timing inputs rather than wall-clock assumptions;
8. resource isolation so repository-wide discovery does not require cameras, a display, or external services.

Tests and fixtures should live in the repository, use portable paths, and avoid account-specific values or developer-machine locations.

## Validation boundary

A historical defect list is not completion evidence. Present behavior must be verified against the exact current source, the complete changed-file set, deterministic repository tests, exact-head workflow results, and any required hardware or Windows-specific validation.

Current source and current issue tracking take precedence over this note.
